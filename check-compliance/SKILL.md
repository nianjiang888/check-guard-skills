# check-compliance 是什么（人格锚：无，纯专业校验域）

check-compliance 是 check-* 系列的新成员，定位是「合规点检护栏（guard-publish 的快检版）」。它不是法务终审（那是人工与 guard-publish 的事），也不是语义级内容审核（那是深度版的事），而是更日常的「合规 lint」——在你把文档、文案或对外发布物推上线之前，先替你把最致命的几类合规红线扫一遍：极限词（广告法风险）、疗效/收益/投资类却无免责声明、统计/百分比/增长却无来源、未脱敏的身份证号/手机号/邮箱 PII、以及对外发布物缺少发布日期/版权年份。

合规红线是最容易被忽略也最容易被认定的发布缺陷：文案读着通顺、构建通过，可一旦「国家级/顶级/全球领先」「治愈/收益」这类表述上线，或把手机号/邮箱写进公开材料，就踩到广告法与个人信息保护的线。check-compliance 要做的，就是把「发布前最后一次合规体检」变成可重跑、可量化、留证据的静态检查，命中后直接给出可修正性报告。

## 能做什么

- 扫文档 / 文案 / 对外发布物里的合规红线（Markdown/文本/配置/代码注释等文本）。
- 极限词判定：国家级/世界级/第一品牌/顶级/极致/百分百/全球领先 等绝对化用语（高）。
- 承诺类判定：出现疗效/治愈/收益/保本/投资/赚钱却无免责声明（中）。
- 数据类判定：出现百分比/倍数/增长/据统计却无来源标注（中）。
- PII 判定：身份证号/手机号/邮箱等未脱敏个人信息（中）。
- 时效判定：对外发布物无任何日期/版权年份（低）。
- 算「验证暴露指数(0-100)」并出「可修正性」报告，退出码 0/1/2/3/4（本包最高为「高」，返回 1；4 保留与系列一致）。

## 边界（重要）

- 仅静态检测，不做全量语义理解，故无法发现「话术包装后的隐性违规」；那是深度版或人工法务的范围。
- 不修改文件、不拦截部署、不感知运行时真实调用、不承诺 100% 准确；是否阻断由 CI 策略决定。
- 与 guard-publish 互补：check-compliance 做合规快检版，guard-publish 做发布深度版，入口不同、互不替代。

## 怎么用

```
python scripts/check.py scan <目录或文件> [报告输出路径]
python scripts/check.py rules
python scripts/check.py ledger <目录>
python scripts/check.py version
```

扫描结束后会输出判定（通过/低/中/高/极端）、验证暴露指数、可修正/不可修正数量、发现项数与预计避免返工工时，并在报告末尾附上机器可读的 `COMPLIANCE_RESULT {...}` 判定块，供 CI 程序化消费。

## 与其他 check 成员的关系

- check-config：校验配置项本身（必填/类型）。
- check-links：校验「引用关系」是否断裂。
- check-spelling：校验「文字与排版」是否干净。
- check-secret-scan：校验「明文密钥/凭证」是否泄露。
- check-compliance（本包）：校验「极限词/缺免责/缺来源/PII/缺日期」等合规红线。
- 后续 check-schema / check-api 等：分别深入数据结构与接口契约。

check-compliance 专注「对外发布物是否踩合规红线」这一层，不做内容正确性判断。
