# 合规点检方法论（check-compliance）

本文件说明 check-compliance 能判定什么、不能判定什么，以及各类规则背后的取舍。

## 一、能确定性判定的（本包范围）

1. 极限词：匹配 `国家级|世界级|第一品牌|唯一指定|顶级|极致|百分百|全球领先|领导品牌|王牌|首选|绝无仅有|史无前例|空前|最强国|最先进` 这类绝对化用语。一旦对外发布即构成广告法风险，定为高级。
2. 缺免责声明：内容出现疗效/治愈/收益/保本/投资/赚钱/获利/增值，且全篇无免责/风险提示/仅供参考/不构成建议/投资有风险 信号，定为中级。
3. 缺数据来源：内容出现 %/百分之/倍/据统计/数据显示/增长，且全篇无来源/出处/引用/据/年报 信号，定为中级。
4. 未脱敏 PII：匹配身份证号（17 位 + 校验位）、手机号（1[3-9] 起 11 位）、邮箱（user@domain.tld），定为中级。
5. 缺发布日期：全篇无任何 `20xx年` / `20xx-xx-xx` / `©20xx` 等日期信号，定为低级。
6. 已接入合规流程（safe 层）：内容出现 ad-review/合规审查/法律顾问/terms-of-service/privacy-policy/法律意见书，仅作鼓励信号，不计入发现项。

## 二、不能判定、也不假装能判定的

- 话术包装后的隐性违规（如「行业领先」换成更隐晦的夸大）：本包不做全量语义理解，会漏报。那是人工法务或深度版的事。
- 真实法律有效性：免责声明是否「足够」免责，需人工判定；本包只检查「有没有」，不判断「够不够」。
- 数据真实性：本包只检查数据「有没有来源标注」，不核实来源是否真实。

## 三、严重度设定

- 高：极限词。广告法红线，一发即风险，定为高级。
- 中：缺免责声明、缺数据来源、未脱敏 PII。对外发布均有实质风险。
- 低：缺发布日期。时效性问题，风险相对轻。
- safe：已接入合规流程，仅鼓励，不计入暴露指数。

## 四、为什么用「模式 + 信号」而非语义理解

语义级合规审核需人工/接法务平台、慢、难进 CI、结果不稳定。本包只用不需语义理解的确定性模式，因此可重跑、可留证据、可进 CI，专门拦住「极限词/缺免责/缺来源/PII/缺日期」这类一眼就能揪的红线。

## 五、如何扩展规则

直接编辑 resources/rules.json，追加 `{"id": "...", "layer": "...", "kind": "regex", "severity": "...", "intent": "...", "pattern"/"req_regex"/"absent_patterns": "...", "recoverable": true, "rec": "..."}` 即可，引擎在每次扫描时实时加载，无需改代码。
