# check-compliance 常见问题（FAQ）

| 场景 | 话术 |
|---|---|
| 「我的文案只是内部草稿，会报吗？」 | 只要被扫到就会报。本包只做静态文本点检，不区分内外部；对外发布物上线前才需要跑，内部草稿可跳过或加入测试白名单。 |
| 「为什么出现『顶级』『全球领先』直接判高级？」 | 因为国家级/世界级/顶级/百分百/全球领先 等是《广告法》明令禁止的绝对化用语，命中即等于踩线，故定高级并建议修复后发布（退出码 1）。 |
| 「文案里写了『收益稳定』但只是举例，会不会误报？」 | 会。缺免责声明在示例文案里是误报高发区；补一句「仅供参考/不构成建议」即可消除，也可把测试文件命名带 test_/example/sample 自动跳过。 |
| 「它会不会漏报话术包装后的隐性夸大？」 | 会。本包不做全量语义理解，隐晦包装的夸大需要人工法务或 guard-publish 深度版来发现。 |
| 「手机号写在公开页也会被扫到？」 | 会。身份证号/手机号/邮箱命中即判中级，提醒脱敏；示例 fixture 里的测试号就是为了演示这点。 |
| 「和 guard-publish 有什么区别？」 | guard-publish 做深度发布审查（分级 + 阻断建议 + 历史留痕），check-compliance 做快检版（模式命中即报），入口不同、互补不替代。 |
| 「扫描会扫到测试文件吗？」 | 文件名含 test_/example/sample 或内容带明确测试标记（fixture/测试专用示例）会被跳过；真实文档即使含 example 等词也不会被跳过，以免漏报真实违规。 |
| 「支持哪些文件类型？」 | 任意文本文件（Markdown/文本/配置/代码注释等），二进制自动跳过。 |
| 「升级后规则变了，旧报告还作数吗？」 | 以当前版本 resources/rules.json 为准。升级时本包会保留旧版说明，建议按新规则重跑一次。 |
| 「怎样加新的合规规则？」 | 直接编辑 resources/rules.json，追加 `{"id": "...", "layer": "...", "kind": "regex", ...}`，引擎实时加载、无需改代码。 |
