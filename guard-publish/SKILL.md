# guard-publish · 发布前合规检查护栏

## 这个包是谁（定位锚点）

guard-publish 是 guard 安全护栏系列的第十二条，专门管**内容/工具对外发布前的合规红线与发布清单**。发布是不可逆动作——极限词、疗效与收益承诺、未脱敏的身份证手机号、没清掉的密钥与内网地址，一旦公开就被缓存转发，收不回来。它不替你拦发布，只在「点发布」前静态过一遍清单，算一笔「发布合规指数」，落实物报告让你看清哪些现在改还来得及、哪些发出去就不可逆，再决定发不发。

适用场景：公众号/自媒体文案发布、产品说明与落地页上线、技能包与工具发布、对外报告与白皮书发出、AI Agent 自动生成内容后的发布前体检。

## 它能做什么 / 不能做什么

能做的：
- 扫描目录，识别 6 类发布风险：发布清单（版本/更新日志/授权缺失）、内容合规（广告法极限词/疗效承诺/收益承诺）、法律声明（无免责声明/数据未标来源）、个人信息（未脱敏 PII/无隐私政策）、凭据与内网（明文密钥/内网地址/调试残留）、以及安全变体。
- 算**发布合规指数（0-100）**，按严重度优先级链给判定：极端 / 高 / 中 / 低。高或极端时返回码 4（已拦截，建议不要直接发布）。
- 标出每条命中的**可整改性**：发布前补上文档或删掉违规表述即可解决的标「可整改」；一旦发布即不可逆、只能轮换或已扩散收回不了的标「不可整改」。这是本包原创的量化点，直接回答「现在改还来不来得及」。
- 量化**安全控制价值**（避免的发布后整改与召回工时），并聚合出 `guard-ledger.md` 价值账本。
- 落**实物报告**（publish_report.md + 机器可读 JSON 尾块），不是日志。

不能做的（诚实边界）：
- 不实际拦发布、不修改内容，决策权在你（看清后果再决定，不硬禁止）。
- 对内容是否真的发布、发到哪个平台、覆盖多少受众无感知。
- 不替代法务合规审查与监管部门认定——给的是「疑似违规」提示，不是法律结论。
- 不覆盖所有细分行业特殊监管要求，规则只覆盖通用红线。
- 不承诺 100%：换个说法表述同一承诺会漏；个别普通用词会被误报。

## 怎么用

```
python scripts/guard.py scan <目录>            # 扫描并出 publish_report.md，高/极端返回码 4
python scripts/guard.py scan <目录> --json     # 同上加 --json 输出结构化命中
python scripts/guard.py rules                  # 列出 12 条发布合规检查规则
python scripts/guard.py ledger <目录>          # 聚合该目录下所有 report 生成价值账本
python scripts/guard.py version                # 打印引擎版本
```

退出码：0 通过 / 1 参数错 / 2 IO·运行错 / 3 未知命令 / **4 已拦截（高/极端风险）**。

## 报告长什么样

扫描后生成 `publish_report.md`，含四节：判定（风险等级 + 发布合规指数 + 可整改性 + 处置建议）、命中汇总、命中清单（含可整改/不可整改标注）、安全控制价值量化，末尾附机器可读 JSON。把报告归档，即是「发布前已按清单核对」的实物证据。

## 与其它 guard 包的关系

- 与 guard-share：share 管「文件发给外部前的内容边界」（发给具体对象、看泄露面），publish 管「内容对外公开发布前的合规」（发给不特定公众、看合规红线）。
- 与 guard-privacy：privacy 管「代码里 PII 字段的处理」（开发态），publish 管「待发布内容里未脱敏的 PII」（发布态）。
- 与 guard-secret：secret 管「密钥字段的存储与调用」，publish 管「待发布文件里的明文密钥」。
- 与 guard-dependency：两者都是发布前门禁，一个看第三方组件（依赖漏洞与投毒），一个看自身内容（合规红线）。
