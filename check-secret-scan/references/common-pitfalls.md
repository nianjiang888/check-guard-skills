# 常见误报与边界（check-secret-scan）

本文件列出发包前已知、且已做规避处理的几类边界，便于使用者理解「为什么有时没报、为什么有时报了但可关」。

## 一、已知前缀命中的边界

- secret-patterns.json 收录的都是「几乎只出现在真实密钥上」的高置信前缀。命中即判极端，是因为这些前缀被滥用的概率极低。
- 若你的代码里确实存在以这些前缀开头的非密钥字符串（极少见），可临时从 secret-patterns.json 移出对应条目，或把文件加入测试白名单。

## 二、硬编码凭证的边界

- SECRET-HARDCODED-CRED 用「关键词 + 赋值 + 引号字面值」三重约束，但仍可能在测试代码里命中占位串（如 `password = "test1234"`）。这类属误报高发区。
- 规避手段：测试文件命名带 test_/example/sample 会被自动跳过；也可在 rules.json 里调高该规则严重度下限或收窄关键词。

## 三、URL 内嵌凭证的边界

- 仅匹配 `协议头://...user:pass@...` 形态，正常不带凭证的地址不会误报。
- 注意本包写法是 `协议头://`（脱敏表述），并非让你在代码里写真实带凭证地址；检测引擎内部用的是标准 URL 正则。

## 四、.env 文件的边界

- 仅按文件名命中 `.env`，不读内容。即便 .env 里只有 `APP_ENV=production` 这种无害值也会报——因为「被提交的 .env」本身就是风险信号（真实凭证常被顺手塞进去）。
- 若确有需要提交的非敏感 .env（少见），可把文件名改成 `.env.example` 规避，或调整规则。

## 五、测试 / 示例文件

- 文件名含 test_/example/sample，或内容带明确测试标记（fixture/测试专用示例）会被跳过，避免把示例里的「故意密钥」报成真实泄露。
- 真实文档即使正文里出现 example 等词，也不会被跳过，以免漏报真实密钥。这是有意为之的取舍：宁可在示例上多扫，也不在真实文档上漏报。

## 六、合规红线

- 本包所有源文件与压缩包均不含明文协议头、真实地址、绝对路径、BOM 与 CRLF，可安全上架分发。
