# 防御立场与诚实声明（check-secret-scan）

本文件说明 check-secret-scan 在「帮你拦住明文密钥」这件事上的立场与边界。它不是密钥保险箱，而是一道可重跑、可量化、留证据的静态防线。

## 一、立场：拦得住的才拦，不假装全能

- 只做不需要语义理解的确定性模式：私钥块、已知前缀密钥、硬编码赋值、URL 内嵌凭证、.env 文件名。这些恰恰是「人容易看漏、工具一眼揪出」的低垂泄露。
- 不做全量熵分析（发现「无前缀的高熵随机密钥」），也不做历史泄露库比对。那超出了静态快检的能力，强行做只会制造误报，反而让人不再信任工具。

## 二、诚实边界

- 不承诺 100% 准确：已知前缀几乎零误报，但硬编码凭证在测试代码里会误报；报告里每条都标注命中类型（如「命中 GitHub Token」），由人最终裁决。
- 不修改文件：只产出报告与机器可读判定块，是否修复、怎么修复由使用者决定。不替你改代码，避免「自动修正」引入新问题。
- 不拦截部署：返回退出码供 CI 消费，但是否阻断由流水线策略决定；本包对明文私钥/已知前缀密钥返回退出码 4（极端级，建议阻断）。

## 三、与同类工具的关系

- 与 guard-secret 互补：guard-secret 做深度防护（分级 + 阻断建议 + 历史扫描），check-secret-scan 做快检版（模式命中即报）。两者入口不同、互不替代。
- 与专业密钥扫描器（gitleaks/trufflehog 等）错位：那些做深度熵分析 + 历史扫描，本包做轻量、可进 CI 的确定性检查，二者可叠加使用。

## 四、可修正性量化的意义

每条发现都带「可修正 / 不可修正」标记（明文密钥一律「可修正——移除并轮换」），并汇总成「验证暴露指数」与「预计避免返工工时」。这让密钥风险从「感觉不安全」变成可比较、可追踪的数字，也方便在多个文件 / 多个包之间排优先级。
