# guard-skill 常见问题（按你会怎么问组织）

## 我下载了个技能，怎么判断能不能装？
先把整个技能目录交给 `guard.py review <目录>`。它会扫红线、查溯源、评权限，最后给一个判定：低/中可直接装，高/极端会拦截（退出码 4）并告诉你为什么。

## 它说"高"，我就绝对不能装吗？
"高"的语义是"拦下，需人工批准后再决定"。意思是这个包命中了高危红线（比如硬编码密钥或远程命令执行），你得看清具体是哪条、是否在你可控的范围内，再决定。不是机器替你拍板，是机器替你看见风险。

## 为什么有的包没 SKILL.md 也被扣分？
SKILL.md 是溯源的入口。没有它，作者、版本、更新时间都无从确认，属于"来历不明"，信任分扣 8 分、判定至少升到"中"。这是 SLSA provenance 思想的直接落地：来历不可验证的制品，默认减信。

## 它能不能 100% 拦住后门？
不能，也不该这么宣传。提示注入是 Transformer 架构级缺陷，学界共识无单点银弹。guard-skill 的价值在于用静态红线覆盖最广、最便宜的第一道防线的 90%，而不是承诺神话。诚实边界写进了报告和参考文档。

## 红线规则我能改吗？
能。`resources/rules.json` 是规则库，新增/调整规则改这个文件即可，不用动引擎代码。每条规则含 id / name / category / severity / pattern，按同样结构加即可。

## 密钥写在代码里，删掉那行就行了吗？
不行。Git 历史里凭据仍在，真正的正确动作是**立即轮换凭据**。审查报告会明确提示"疑似已泄露，请轮换"，而不是只说"删掉"。

## 审查出来的"价值账本"是干嘛的？
安全工具最大的痛点是"什么都没发生 = 看起来没用"。guard-skill 把每次拦截折算成"估算避免 N 小时事故响应"，累积成 `guard-ledger.md`。这是你续用和向别人证明它有用的唯一理由。

## 误报怎么办？
红线命中有时会落在正常代码上（比如教学示例里写了 `os.system`）。"中"级信号只提示不阻断；若确属误报，可在审查报告里人工标注放行。不要把告警当耳旁风，也不要一见告警就全点忽略——告警疲劳会杀死安全产品。

## 和 self-protect 有什么区别？
self-protect 管"AI 自己别做危险事"（向内约束），guard-skill 管"装第三方包之前先看清它什么来路"（向外防御）。一个约束己方，一个审查他人。
