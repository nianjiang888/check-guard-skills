版本 v1.0.0　评估时间 2026-09-06　评估对象：check-gov-doc-format

打分口径：5 分制，取整数与半档。任一维低于 5.0 必须写明具体问题，不许用"待优化"这类空话糊过去。

## T — Task 契约　4.5 / 5

**做对的**：四条命令（scan / rules / ledger / version）与 check 系列其他成员完全同构，退出码 0/1/2/3 语义明确。报告分两节——"自动检出问题"与"人工核对清单"，节界清晰：第一节每行带国标条款号，第二节每项带标准值。判定块 GOVDOC_RESULT 八字段固定（verdict / exposure_index / fixable / unfixable / findings / manual_items / avoid_rework_hours / scan_time），冒烟测试逐项断言。

**扣 0.5 的原因**：与 check-tender-rejection 同一个契约缺口——只读 .md/.txt，Word/WPS 需先转文本。公文 100% 是 .docx 起家的，这个转换摩擦在本域比标书域还大。

**下一步**：加 `--from-docx` 前置转换，或至少在 SKILL.md 给出可复制的转换命令行。

## R — Robustness 鲁棒性　4.5 / 5

**做对的**：规则加载期逐条正则编译校验，非法正则打印规则 id 并跳过（本包实测：注入坏正则后引擎继续工作，只出警告不崩）；单文件 8 MB 读取上限，超限跳过并警告；规则文件读不了走 _die 退出码 2；人工核对项按文种条件化输出，不会给一封普通通知列出一堆信函格式要求。

**说明**：规则正则校验和文件大小上限这两个缺口在 check-tender-rejection v1.0.0 的自评里被明确记为问题，本包开工时直接修掉了，没有再继承。这是系列内部的能力传递，不算自我表扬，算流程改进。

**扣 0.5 的原因**：`_validate_rules` 只校验正则可编译，不校验语义组合。比如一条 regex 规则同时只写 absent_patterns 没写 pattern，逻辑上合法但可能不是规则作者的本意；再比如 severity 拼错（"极高"）不会被拦，会静默落到 SEV_WEIGHT 默认值 3，指数算错但没有任何提示。

**下一步**：加载期加字段枚举校验（severity ∈ 四档、layer ∈ 已知分层、kind ∈ 已知机制），违者警告并跳过。

## A — Applicability 适用性　4.0 / 5

**做对的**：45 条规则（22 自动 + 23 人工）全部带 GB/T 9704-2012 或中办发〔2012〕14号具体条款号，`basis` 字段可追溯到款。这是本包的立身之本——用户拿报告去和办公室核对时，每条都能指到"国标第几条第几款"，而不是"建议你检查一下"。人工清单按文种条件化（信函/命令/纪要专项只在对应要素出现时输出），适用面覆盖党、政、事业单位、国企办公场景。

**扣 1.0 的原因**：两类真实的覆盖缺口。

1. 地方变体未覆盖。部分省份对发文字号有地方细则（如联合行文的机关排列顺序），规则库只按国标中央口径，地方差异只能靠人工核对兜住。
2. 党的机关公文（如"中共中央文件"式版头）与军队公文的格式依据另有细则，本包规则按党政通用口径写，对这两类会多报或少报个别项。边界在 SKILL.md 有声明，但声明不能替代覆盖。

**下一步**：先做地方细则的事实核查清单放进 references，视需求再做规则分化。

## C — Clarity 清晰度　4.5 / 5

**做对的**：两节报告结构本身就是透明度设计——自动判定和人工核对物理隔开，不存在"机器猜的混在人要核的里"的灰区。每条发现项带"国标条款 + 说明 + 可修正性 + 整改建议"四件套。工时估算在报告正文直接标注"量级估算，按严重度基数累加，非精算"（这是 check-tender-rejection 自评里 clarity 扣分项的直接修复）。`references/gb9704-methodology.md` 把两份权威文件、条款对照速查、判定语义约定（同义词组 OR、缺失判定、严重度封顶）单独成篇，专业性可审计。

**扣 0.5 的原因**：人工核对清单里部分"标准值"写法仍偏简（如"右空四字"），对没读过国标的人不够自明——四字是相对什么空？版心还是页边？要配合 methodology 文档才完整。报告是独立交付物，理想状态下应自带解释。

**下一步**：标准值字段补足参照系（如"成文日期右空四字（相对版心右边缘，四字=4×当前字号字宽）"）。

## E — Evidence 实物证据　5.0 / 5

证据链完整、可复现：

1. 四份样例报告全部由引擎实跑产出，`python scripts/smoke_test.py` 一键复现，四档判定（通过/中/高/高）与发现项数、违规指数、退出码全部断言通过。
2. clean 样例 0 命中 0 误报。国标类检查最容易犯"把正确写法当违规"的错（比如把正文里合法的书名号引用报出来），clean 样例是压这个错的最直接证据——书名号规则被限定为只查标题特征，正文引用不触发。
3. 规则库静态校验全绿：45 条全部带 basis 条款号、全部正则可编译（离线脚本 + 引擎加载期双重校验）、严重度枚举无越档值。
4. 权威参数（版心 156×225mm、页边距 37/35/28/26mm、每面 22 行 28 字、15 文种名单）来自正式核实而非记忆，来源写在 methodology 文档里。
