# RAG 投毒与上下文溢出：理论底座

## 一、RAG 的数据层攻击面

检索增强生成（RAG）把外部文档拼进上下文再让模型回答。攻击者可向知识库注入恶意文档，使毒内容在检索阶段被选中、拼进上下文，从而引导模型输出——这就是 RAG 投毒（数据层间接注入）。

> 引用：Zou et al., *PoisonedRAG* (2024)；Greshake et al., 间接提示注入调查 (2023)。

## 二、两个放大因子

1. **上下文预算无上限**：检索结果不加 `max_tokens` / `top_k` / 窗口截断，不可信长文占比越高，模型越易被「淹没」——指令（系统提示）被挤到上下文边缘，数据里的注入短语反而占主导。
2. **来源无标注**：外部文档直接进上下文却不标「不可信」，模型无法区分「这是指令」还是「这是待处理的数据」。

本引擎据此设两条规则：
- `MEM-RAG-NOCAP`（中）：检索无长度/预算上限。
- `MEM-RAG-UNTRUSTED`（高）：不可信文档喂上下文且无信任标注。

## 三、缓解的工程实践

| 做法 | 作用 |
|------|------|
| 检索结果设 `top_k` + `max_tokens` 上限 | 限制不可信内容占比 |
| 外部内容打「不可信」标签、隔离渲染 | 让模型分得清指令与数据 |
| 按信任级排序，可信源优先 | 降低毒内容被选中概率 |
| 召回内容做指令短语检测 | 在入上下文前拦下注入 |

## 四、诚实边界

静态检测只能看到「代码是否设了上限 / 是否标注来源」，看不到运行时真实召回了什么文档。因此本引擎判定为「中/高」风险时，表达的是「护栏缺失」，而非「已确认被投毒」。决策权仍在人。
