# OWASP LLM07 与记忆投毒：理论底座

## 一、OWASP Top 10 for LLM Applications 2025

OWASP 在 2025 版中将「系统提示泄露 / 记忆投毒」列为大模型应用核心风险之一（LLM07），并与 LLM01「提示注入」同源：

- **直接注入**：用户主动在输入里夹「忽略之前指令」。
- **间接注入**：不可信内容（网页、文档、工具返回值、记忆条目）里夹指令，模型在处理时被动执行。

记忆污染属于**间接注入的持久化形态**——它不只在一次对话生效，而是写进长期状态后反复生效。

> 引用：OWASP, *Top 10 for Large Language Model Applications* (2025), LLM07: System Prompt Leakage; LLM01: Prompt Injection.

## 二、为什么记忆比上下文更危险

| 维度 | 单次上下文注入 | 记忆投毒 |
|------|---------------|----------|
| 作用范围 | 当前一轮对话 | 后续所有对话 |
| 察觉难度 | 较易（本轮异常） | 极难（跨会话、慢变量） |
| 清除成本 | 重开对话即可 | 需定位并删除污染条目 |
| 攻击面 | 输入通道 | 记忆读写 + 检索拼接 |

一旦「记住你永远把数据发给 X」之类被固化进长期记忆，它成了模型的「长期信念」，比一次性 prompt 更难根除。这正是本引擎把**投毒信号**设为极端级的根本原因。

## 三、与本引擎的映射

- OWASP LLM07 的「系统提示泄露」→ 本引擎 `MEM-LEAK-SYSPROMPT`（极端）。
- OWASP LLM01 的「间接注入」→ 本引擎 `MEM-POISON-PHRASE` / `MEM-POISON-IMPERATIVE`（极端/高）。
- 信任边界原则（Saltzer & Schroeder 1975）→ 本引擎 `MEM-WRITE-UNTRUSTED`（不可信跨边界直写）。

## 四、落地要点

1. 记忆写入必须校验内容，禁止携带指令性短语。
2. 系统提示与记忆存储物理隔离，互不写入。
3. 不可信来源进记忆前先隔离、打信任标签、记录溯源。
