# 配置常见坑位（check-config 覆盖的清单）

| 坑位 | 典型表现 | 严重度 | 为何危险 |
|---|---|---|---|
| 明文密钥 | `password = "x8f2k..."` 写在配置文件 | 极端 | 仓库/镜像泄露即凭据泄露，必须轮换 |
| 明文 http | 内部调用 `http:(?=//)…` | 高 | 传输可被中间人窃听 |
| 硬编码绝对路径 | `data_dir = /opt/app/data` | 高 | 换机器/容器即失效 |
| 端口超范围 | `port = 99999` | 高 | 服务起不来，且难定位 |
| 连接配置缺鉴权 | 有 `host` 没有 `token` | 高 | 连上了却无权限或连错环境 |
| 生产开 debug | `env=prod` 且 `debug=true` | 中 | 泄露栈帧/内部信息，性能下降 |
| 日志级别非法 | `log_level = verboseee` | 中 | 日志异常或丢失关键记录 |
| 废弃键 | `enable_ssl = false` | 低 | 语义已变，误导维护者 |

## 误报控制

- 示例/测试文件（文件名或内容含 example/sample/demo/placeholder/your_/xxxx 等）跳过扫描。
- 明文密钥规则用负向预查排除占位符值（your_/changeme/xxx 等），避免示例密钥被误报。
- 复合规则（缺鉴权字段、生产开 debug）要求「同时命中多个条件」才提示，降低单条件误报。

## 不属于本包范围

- 运行时动态配置热更新。
- 密钥轮换的具体执行（那是运维/guard 的事）。
- 代码逻辑层面的配置使用是否正确（静态文本检查看不到调用关系）。
