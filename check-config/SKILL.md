# check-config 是什么（人格锚：无，纯专业校验域）

check-config 是 check-* 系列的第一个成员，定位是「配置/参数文件的通用校验护栏」。它不是安全扫描器（那是 guard 的事），而是更日常的「lint」——在你把配置推上线之前，先替你把明显的坑扫一遍：必填鉴权项有没有漏、端口是不是填成了 99999、密钥是不是明文写在文件里、生产环境是不是还开着 debug、内部调用是不是用了明文 http。

配置错误是最常见也最隐蔽的线上故障源：本地能跑、上了生产就崩，往往就是某个参数类型不对、某个环境变量没注入。check-config 要做的，就是把这个「部署前最后一道肉眼复核」变成可重跑、可量化、留证据的静态检查。

## 能做什么

- 扫配置/参数文件（ini / yaml / toml / json / env / properties 等文本配置），不挑框架。
- 按严重度分级：极端 / 高 / 中 / 低。
- 每条发现标注「可修正 / 不可修正」——明文密钥一旦写进文件，改掉只能算「缓解」，真正安全要轮换，所以标为不可修正。
- 算**验证暴露指数（0–100）**和**预计避免返工工时**，把「配置雷区」折成可感知的数字。
- 产出机器可读的判定块（JSON 尾块）和可复核的报告文件（实物证据）。

## 边界（诚实声明）

- 仅静态检测，**不修改你的文件、不拦截部署**、不感知运行时真实行为。
- 判定基于文件可见内容；不承诺 100% 准确，误报会杀死产品，故用白名单 + 复合规则压制误报。
- 价值量化（避免返工工时）为估算，真实以你的故障记录为准。
- 与 guard-secret / guard-publish 是互补关系：check 做「快检版」（扫一眼报出来），guard 做「深度防护版」（分级 + 阻断建议）。

## 怎么用

```
python scripts/check.py scan <配置目录或文件> [报告输出路径]
python scripts/check.py rules      # 列出全部规则
python scripts/check.py ledger <目录>   # 聚合价值量化（CI 看板用）
python scripts/check.py version    # 打印版本
```

退出码：0=干净 / 1=有发现 / 2=IO 或运行错 / 3=未知命令 / 4=发现极端级问题（建议阻断发布）。
