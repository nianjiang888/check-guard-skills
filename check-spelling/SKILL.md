# check-spelling 是什么（人格锚：无，纯专业校验域）

check-spelling 是 check-* 系列的第三个成员，定位是「文字质量与排版检测护栏」。它不是实时校对器（那是语义层的事），也不是安全扫描器（那是 guard 的事），而是更日常的「文字 lint」——在你把文档、代码注释或配置说明推上线之前，先替你把明显的文字坑扫一遍：常见错别字（帐号→账号）、中文叠字（的的/了了）、英文相邻重复（the the）、中文后跟半角标点、Markdown 标题层级跳跃、中英文之间缺空格。

错别字是最容易被读者一眼看穿、也最影响专业度的发布缺陷：功能正常、构建通过，可读者一看「帐号」「登陆」就知道这文档没过校。check-spelling 要做的，就是把这个「发布前最后一次文字体检」变成可重跑、可量化、留证据的静态检查。

## 能做什么

- 扫文档 / 代码注释 / 配置说明里的文字与排版问题（Markdown、文本、reStructuredText）。
- 错别字检测：基于高频错→对词典，命中即报，并标注「错 → 对」。
- 叠字检测：中文功能词相邻重复（的的/了了）、英文相邻重复（the the）。
- 排版卫生：中文后跟半角标点、中英文之间缺空格（仅散文类扩展名）。
- 结构一致性：Markdown 标题层级跳跃（如一级直接到三级）。
- 算「验证暴露指数(0-100)」并出「可修正性」报告，退出码 0/1/2/3（本包最高严重度为「中」，不触发 4）。

## 边界（重要）

- 仅静态检测，不做语义理解，无法判断「用词是否贴切、语句是否通顺」。
- 不修改文件、不拦截部署、不承诺 100% 准确；是否阻断由 CI 策略决定。
- 与 guard 互补：check-spelling 做文字质量快检版，guard 做安全深度版，入口不同、互不替代。

## 怎么用

```
python scripts/check.py scan <目录或文件> [报告输出路径]
python scripts/check.py rules
python scripts/check.py ledger <目录>
python scripts/check.py version
```

扫描结束后会输出判定（通过/低/中/高/极端）、验证暴露指数、可修正/不可修正数量、发现项数与预计避免返工工时，并在报告末尾附上机器可读的 `SPELL_RESULT {...}` 判定块，供 CI 程序化消费。

## 与其他 check 成员的关系

- check-config：校验配置项本身（必填/类型/密钥）。
- check-links：校验「引用关系」是否断裂。
- check-spelling（本包）：校验「文字与排版」是否干净。
- 后续 check-schema / check-api 等：分别深入数据结构与接口契约。

check-spelling 专注「字对不对、排版整不整齐」这一层，不做内容正确性判断。
