# 常见误报与边界（check-spelling）

本文件列出发包前已知、且已做规避处理的几类边界，便于使用者理解「为什么有时没报、为什么有时报了但可关」。

## 一、错别字词典的边界

- 词典只收高频稳定错误，不穷尽所有错词。漏报不代表文本正确，仅代表不在本轮词典内。
- 部分词存在「异形词」争议（如「其他 / 其它」「人才 / 人材」），本包不强行统一，避免误改作者有意为之的写法。
- 错误词作为子串命中，若某正确词恰好包含错误词片段（极少见），可能误报；遇到可临时移出词典。

## 二、中英文缺空格的边界

- 该规则仅作用于散文类扩展名（.md/.txt/.rst/.markdown），刻意不扫 .py/.js 等代码文件——代码里 `中文JSON`、注释中的紧凑写法不应被当成错误。
- 是否强制空格取决于团队排版风格。若团队不要求 CJK 空格，可在 rules.json 中删去 SPELL-CJK-SPACE 规则或整体关闭。

## 三、标题层级跳跃的边界

- 仅作用于 Markdown（.md/.markdown），且每个文件只报一次（避免同一文件多次跳跃刷屏）。
- 某些文档确实采用非连续层级作为视觉分隔，属有意设计；此类可按需关闭该规则。

## 四、测试 / 示例文件

- 文件名含 test_/example/sample，或内容带明确测试标记（fixture/测试专用示例）的文件会被跳过，避免把示例里的「故意错字」报成真实缺陷。
- 真实文档即使正文里出现 example 等词，也不会被跳过，以免漏报真实错字。这是有意为之的取舍：宁可在示例上多扫，也不在真实文档上漏报。

## 五、合规红线

- 本包所有源文件与压缩包均不含明文协议头、真实地址、绝对路径、BOM 与 CRLF，可安全上架分发。
