# check-spelling 常见问题（FAQ）

| 场景 | 话术 |
|---|---|
| 「我的文档能跑、能读，还要查错别字吗？」 | 功能正常不等于文字干净。读者一眼看到「帐号」「登陆」就会对专业度打折扣，check-spelling 在发布前替你扫一遍这类低垂的坑。 |
| 「它会不会把我的专有名词当成错字？」 | 不会全量扫。词典只收高频稳定错误（约 30 组），未收录的生僻词会漏报而非误报；若某正确词恰好含错误片段，可临时移出 typos.json。 |
| 「为什么中英文缺空格只在散文里报？」 | 因为代码文件（.py/.js）里 `中文JSON`、紧凑注释是常态写法，不该被当成错误。该规则刻意限定 .md/.txt/.rst，避免误伤代码。 |
| 「标题层级跳跃为什么只报一次？」 | 同一文件多次跳跃会刷屏，失去重点。每个文件只报第一处跳跃，先修最明显的那一个。 |
| 「它会不会联网做深度校对？」 | 不会。check-spelling 只做不需要语义理解的确定性规则，不发起任何网络请求，因此可重跑、可进 CI、不受网络影响。 |
| 「和其它 check 成员什么关系？」 | check-config 查配置项、check-links 查引用断裂、check-spelling 查文字排版；同属 check-* 系列，各管一层、互不替代。 |
| 「扫描会扫到测试文件吗？」 | 文件名含 test_/example/sample 或内容带明确测试标记（fixture/测试专用示例）会被跳过；真实文档即使含 example 等词也不会被跳过，以免漏报真实错字。 |
| 「支持哪些文件类型？」 | Markdown（.md/.markdown）、纯文本（.txt）、reStructuredText（.rst）。二进制与代码会被跳过或按规则受限。 |
| 「升级后规则变了，旧报告还作数吗？」 | 以当前版本 rules.json 为准。升级时本包会保留旧版说明，建议按新规则重跑一次。 |
| 「能不能不报某条规则？」 | 可以。直接在 resources/rules.json 里删掉对应规则，或调整其 severity，引擎实时加载、无需改代码。 |
