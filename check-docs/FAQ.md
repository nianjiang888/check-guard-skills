# check-docs 常见问题（FAQ）

| 场景 | 话术 |
|---|---|
| 「我的 README 写了『已实现』，但代码还没做完，会报吗？」 | 会。DOCS-STALE-TODO 按「完成声明（已实现/已支持/已完成/已上线/available）+ 未完成标记（TODO/FIXME/待办/计划中/未实现）」双重命中判定，这种文档与状态不符正是它的目标。 |
| 「文档里的 {{变量名}} 算占位符吗？」 | 算。DOCS-PLACEHOLDER 命中 {{}} 形态、TBD、待补充、占位符、coming soon，对外发布会露出半成品，故定中级并建议补全或移除。 |
| 「引用了一张图片 missing-diagram.png 但文件确实在，为什么还报？」 | 引擎按相对路径在扫描根内解析，找不到即判缺失（DOCS-BROKEN-LINK，高）。若文件在仓库其他位置，调整引用路径或把文件放到引用处即可消除。 |
| 「../ 引用为什么算问题？」 | DOCS-ESCAPE-REF 判定引用用 ../ 逃出仓库根，可能指向无关或越权位置，故定中级并建议改仓库内相对路径；这不影响正常运行，但属结构隐患。 |
| 「标题从 # 直接到 ### 会怎样？」 | DOCS-HEADING-SKIP 定为低级：大纲结构断裂、可读性差，建议补齐中间层级或调整标题级别。 |
| 「和 check-links 有什么区别？」 | check-links 查所有引用（含外链、锚点重复）是否断裂；check-docs 只关心文档自身的一致性与结构（死文件引用 + 占位 + 标题层级），更聚焦、更易在发布前快速过一遍。 |
| 「扫描会扫到测试文件吗？」 | 文件名含 test_/example/sample 或内容带明确测试标记（fixture/测试专用示例）会被跳过；真实文档即使含 example 等词也不会被跳过，以免漏报真实缺陷。 |
| 「支持哪些文件类型？」 | 任意文本文件（Markdown/HTML/配置等），二进制自动跳过；标题层级检查仅对 .md/.markdown/.rst 生效。 |
| 「升级后规则变了，旧报告还作数吗？」 | 以当前版本 rules.json 为准。升级时建议按新规则重跑一次，对比 DOCS_RESULT 判定块。 |
| 「怎样加新的文档规则？」 | 直接编辑 resources/rules.json，追加 {"id": "...", "layer": "...", "kind": "regex", ...}，引擎实时加载、无需改代码。 |
