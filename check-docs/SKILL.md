# check-docs 是什么（人格锚：无，纯专业校验域）

check-docs 是 check-* 系列的「文档与代码一致性护栏」。它不是文档生成器（那是写作的事），也不是全文语义校对（那是自然语言处理的活），而是更日常的「文档 lint」——在你把文档、说明或 README 推上线之前，先替你把最常见、最容易被看漏的文档缺陷扫一遍：声称已实现却还挂着 TODO、没填的占位符、相对引用指向一个不存在的文件、引用用 ../ 逃出仓库根、标题层级从一级直接跳到三级。

文档/页面/锁文件「看起来没问题」往往只是没被认真扫过。这些缺陷不会让构建失败，却会在发布后被人点开死链、被视障用户卡住、被供应链投毒、被卡死的流水线拖垮。check-docs 要做的，就是把这道「发布前最后一次体检」变成可重跑、可量化、留证据的静态检查。

## 能做什么

- 扫文档 / 说明 / README 里的「文档与代码不一致」问题（Markdown/HTML/任意文本）。
- 语义级判定：声称已实现/已支持/已完成却还含 TODO/FIXME/待办（中）、仍含未填占位符 {{}}/TBD/待补充（中）。
- 结构级判定：相对引用的文件/资源缺失（高）、引用路径逃出仓库根（中）、Markdown 标题层级跳跃超过一级（低）。
- 鼓励信号：已接入文档同步流程（doc-sync/文档同步等），仅正向标记。
- 算「验证暴露指数(0-100)」并出「可修正性」报告，退出码 0/1/2/3/4。

## 边界（重要）

- 仅静态检测，不读代码运行时、不做全文语义理解，故无法发现「文档描述与逻辑实质不符」这类需要推理的矛盾。
- 不修改文件、不拦截部署、不感知真实点击行为、不承诺 100% 准确；是否阻断由 CI 策略决定。
- 与 check-links 互补：check-links 查所有引用关系是否断裂（含外链/锚点），check-docs 聚焦文档自身的一致性与结构（死文件引用 + 占位 + 标题层级）。

## 怎么用

```
python scripts/check.py scan <目录或文件> [报告输出路径]
python scripts/check.py rules
python scripts/check.py ledger <目录>
python scripts/check.py version
```

扫描结束后会输出判定（通过/低/中/高/极端）、验证暴露指数、可修正/不可修正数量、发现项数与预计避免返工工时，并在报告末尾附上机器可读的 `DOCS_RESULT {...}` 判定块，供 CI 程序化消费。

## 与其他 check 成员的关系

- check-config：校验配置项本身。
- check-links：校验「引用关系」是否断裂（含外链/锚点）。
- check-spelling：校验「文字与排版」是否干净。
- check-secret-scan：校验「明文密钥/凭证」是否泄露。
- check-schema：校验「数据 schema 字段约束」是否缺失。
- check-docs（本包）：校验「文档与代码一致性」——声称完成却留 TODO、占位符未填、引用的文件不存在、标题层级跳跃。
- 后续 check-lockfile / check-accessibility / check-ci：深入依赖锁定、可访问性、CI 配置。

check-docs 专注「文档说出来的是不是真的、结构是不是干净」这一层。
