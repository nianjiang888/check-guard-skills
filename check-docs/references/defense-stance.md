# 防御立场与诚实声明（check-docs）

本文件说明 check-docs 在「帮你拦住文档与代码一致性护栏雷区」这件事上的立场与边界。它不是执行/渲染引擎，而是一道可重跑、可量化、留证据的静态防线。

1. 只做不需要语义理解的确定性模式：声称完成却留 TODO、未填占位符、死文件引用、引用逃出仓库根、标题层级跳跃。这些恰恰是「人容易看漏、工具一眼揪出」的低垂文档硬伤。
2. 不做全文语义推理（发现「文档描述与代码逻辑实质不符」），也不做外链可达性探测。那超出了静态快检的能力，强行做只会制造误报，反而让人不再信任工具。
3. 不承诺 100% 准确：死文件引用几乎零误报，但占位符/完成声明在命名巧合时会误报；报告里每条都标注命中类型（如「文档引用的相对文件/资源不存在（缺失：nope.md）」），由人最终裁决。
4. 不修改文件：只产出报告与机器可读判定块，是否修复、怎么修复由使用者决定。不替你改文档，避免「自动修正」引入新问题。
5. 不拦截部署：返回退出码供 CI 消费，但是否阻断由流水线策略决定；本批规则最高严重度为「高」，未启用极端级（退出码 4 保留给未来扩展）。
6. 每条发现都带「可修正 / 不可修正」标记（文档类缺陷一律「可修正——补全或修正对应内容」），并汇总成「验证暴露指数」与「预计避免返工工时」，让文档风险从「感觉不规范」变成可比较、可追踪的数字。
