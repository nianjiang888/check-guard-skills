# 文档与代码一致性护栏 方法论（check-docs）

本文件说明 check-docs 能判定什么、不能判定什么，以及各类规则背后的取舍。

## 一、能确定性判定的（本包范围）

1. 声称完成却未完成：文档出现「已实现/已支持/已完成/已上线/available」等完成声明，却同时含 TODO/FIXME/待办/计划中/未实现 等未完成标记，定为中级。
2. 未填占位符：文档仍含 {{}}/TBD/待补充/占位符/coming soon，对外发布会露半成品，定为中级。
3. 死文件引用：文档用相对路径引用的文件/资源在仓库内解析不到，读者点开即 404，定为高级。
4. 引用逃出仓库根：引用路径用 ../ 逃出扫描根，可能指向无关或越权位置，定为中级。
5. 标题层级跳跃：Markdown 标题从一级直接跳到三级（跨越超过一级），大纲结构断裂，定为低级。
6. 已接入文档同步：命中 doc-sync/文档同步/文档与代码一致性，定为安全变体（仅鼓励信号，不计入发现项）。

## 二、不能判定、也不假装能判定的

1. 文档描述与代码逻辑实质不符（例如文字说『支持并发』但实现是单线程）：本包只做确定性模式匹配，不读运行时、不做语义推理，会漏报这类需要理解的矛盾。
2. 外链是否真的可达：那是 check-links 的范围（含网络可达性），本包只判相对文件是否存在于仓库内。
3. 文档「写得好不好读」：可读性主观判断超出静态 lint，本包只报结构级硬伤（占位、死链、层级跳跃）。

## 三、严重度设定

- 高：死文件引用（DOCS-BROKEN-LINK）。读者点开即 404，是最直接暴露的文档缺陷。
- 中：声称完成却留 TODO、未填占位符、引用逃出仓库根。这三类都让文档与真实状态/结构脱节，故定为中级并建议修复。
- 低：标题层级跳跃。可读性缺口，但不如结构缺失致命。
- 安全变体：已接入文档同步流程，仅鼓励信号，不计入发现项、不影响判定。

## 四、为什么用「模式匹配」而非实时执行/渲染

实时语义理解需要接大模型或人工，慢、贵、难进 CI、结果不稳定。本包只用不需要语义理解的确定性模式，因此可重跑、可留证据、可进 CI，专门拦住「声称完成却没完成 / 占位没填 / 引用的文件不存在 / 标题层级跳跃」这类一眼就能揪的文档硬伤。

## 五、如何扩展规则库

直接编辑 resources/rules.json，追加 {"id": "...", "layer": "...", "kind": "regex", ...} 即可，引擎在每次扫描时实时加载，无需改代码。
