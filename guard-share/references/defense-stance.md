# 设计立场与诚实边界（guard 系列统一）

## 立场：看清后果再决定，不硬禁止

guard 系列每个包都守同一条线：**护栏的价值在让人看清风险，不在替人拦**。具体到 guard-share（外发文件泄露检查）：

- 外发是业务必需——给客户发方案、给合作方发清单、对外发资料，都是正常动作，全禁等于不干活。
- 硬禁止会逼人把文件改成图片、塞进加密压缩包、或用私人微信私下传——这些「绕过去的发法」反而完全脱离了任何审查，结局更糟。
- 所以本工具只做量化与提示：外发泄露指数、可溯源性、避免损失工时，决策权交还发送人。

## 诚实边界（必须写明，不承诺 100%）

1. **只静态检测，不实际拦发送。** 工具跑完，文件该发还发。拦不拦是你的运行时策略（邮件网关、审批流）。
2. **对文件最终去向无感知。** 是否真发出、发给谁、通过什么渠道——本工具不知道。
3. **启发式正则，漏报与误报并存。** 变量改名、间接引用、解密再处理都会漏；个别普通 `name`/`email` 会被误报。规则仅作提示。
4. **可溯源性不是「已溯源」保证。** 维度只提示「这些泄露是否带标记可追」，是否真能追到须结合标记部署与人工确认。
5. **不评估数据真实敏感度，只量化静态可见风险。** 一行身份证号字面可能是测试数据，也可能是真号——引擎分不清，需人工结合业务判断。

## 退出码约定（全系列一致）

| 码 | 含义 |
|----|------|
| 0 | 通过（低危或无命中） |
| 1 | 参数错（缺目录 / 路径不存在） |
| 2 | IO·运行错（资源解析失败 / 报告写入失败） |
| 3 | 未知命令 |
| 4 | 已拦截（高/极端风险，建议不要直接外发） |

## 安全控制价值量化

把「没发生的泄露」折算成可感知数字：极端 8h / 高 4h / 中 1h / 低 0h 的溯源补救与泄露处置工时。这是把合规成本语言化，让「加个水印、定个密级」的投入有依据，而非拟人化包装。

## 与系列其他包的衔接

- 与 guard-privacy：privacy 管「代码里的 PII 字段处理」（字段级、开发态），share 管「整个文件外发前的内容边界」（文件级、外发态）。同一份 PII，开发时看脱敏，外发时看能不能发。
- 与 guard-secret：secret 管「密钥字段的存储与调用」，share 管「密钥字面随文件外发」——前者防代码里泄露，后者防文件里泄露。
- 与 guard-network：network 管「代码里的外联通道」（数据怎么出去），share 管「文件外发的边界」（文件怎么出去）——通道与文件两条线。
- 与 guard-publish（规划中）：publish 管「发布前的综合合规」，share 是其中「外发内容边界」这一专项。
