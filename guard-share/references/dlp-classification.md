# 数据分级分类与外发 DLP（guard-share 理论根基）

## 一、为什么外发前要查边界

文件一旦点「发送」，里面的内容就脱离了你的掌控。对方能不能转发、截图、存到第三方云盘，你都无法控制。所以在「点发送」之前花一分钟看清这份文件到底含了什么，是性价比最高的防护动作。

DLP（数据防泄露，Data Loss Prevention）行业的一般做法分三步：

1. **发现（Discover）**：扫描文件/仓库，识别哪些内容属于敏感类别。
2. **分类（Classify）**：给内容定级（公开 / 内部 / 秘密 / 机密），决定谁能看、能发到哪。
3. **处置（Act）**：对敏感内容加密、脱敏、加标签、加水印，或直接拦截。

本工具落在第 1、2 步——以外发前的静态内容审查，把「这份文件到底含了哪些敏感类别」说清楚，并提醒你是否定了密、加了溯源标记。

## 二、敏感内容的四类边界

| 类别 | 典型内容 | 外发后果 |
|------|----------|----------|
| PII（个人可识别信息） | 身份证号、手机号、邮箱、住址 | 侵犯隐私、触发个保法合规义务、可被社工/诈骗利用 |
| 密钥/凭据 | API Key、Token、私钥、账号密码 | 身份冒用、配额盗刷、系统被控 |
| 商业敏感 | 报价、底价、合同金额、成本、路线图 | 谈判底牌暴露、利润被吃、竞争情报泄露 |
| 内部文档 | 内网地址、组织架构、员工名单、薪酬 | 运行信息暴露、被定向攻击或勒索 |

这四类不是并列的「危险等级」，而是「泄露面」——同一份文件可能同时踩中两类（如一份报价单同时含客户联系人和底价），审查时要全看，不能只看最显眼的一类。

## 三、数据分级分类是 DLP 的前置动作

ISO/IEC 27001 附录 A.8 要求对信息按敏感度分级；各企业的数据分类规范也把「公开 / 内部 / 秘密 / 机密」作为基础分层。分了级，才知道一份文件「能不能发、发给谁、要不要加密」。

本工具检测的 SHARE-CLASSIFY-MISSING 正是反方向的问题——**文件已经写了敏感内容，却通篇找不到任何密级标签**。这说明它是一份「没定密就准备外发」的文件，风险不在内容本身，而在「没人对这份文件的去向负责」。

## 四、溯源标记：泄露后的最后一道抓手

即便做好了分级与加密，文件仍可能通过截图、转发、离职带走在事后泄露。这时唯一能追到「经谁、哪个副本流出」的，是文件里预先埋好的**溯源标记**：

- **数字水印**：把接收者身份、副本编号嵌入文档（可见或不可见）。
- **蜜标 / Canary Token**（Thinkst 提出并产品化）：在文档里埋一段看似正常、实则唯一的标记（专属链接、伪账号）。文档被打开即触发告警，定位泄露源。

本工具把「含敏感内容但无溯源标记」列为**不可溯源**状态——意思是：这份文件一旦泄露，你事后追不回来、查不到是谁。这正是 可溯源性 维度要衡量的核心。

## 五、诚实边界

- 分级分类的最终判定需要业务语境，正则只能提示「疑似敏感」，不能替代人工定密。
- 溯源标记检测是「有 / 无」判断，不校验标记真伪；伪造水印不在本工具职责内。
- 本工具不实际拦发送，它给的是决策依据，不是免责证明。
