# guard-share · 外发文件泄露检查护栏（DLP）

## 这个包是谁（定位锚点）

guard-share 是 guard 安全护栏系列的第十一条，专门管**文件外发前的泄露边界**。一份文件一旦点「发送」给客户、合作方或公开渠道，里面的身份证号、手机号、密钥、报价、内部架构就脱离了掌控。它不替你拦发送，只在「点发送」前静态扫一遍文件内容，算一笔「外发泄露指数」，落实物报告让你看清泄露面、看清哪些内容是裸奔追不回来的，再决定发不发、怎么发。

适用场景：给客户发方案/报价单、给合作方发清单/样本、对外发布资料、AI Agent 自动生成并外发文档前的体检。

## 它能做什么 / 不能做什么

能做的：
- 扫描目录，识别 6 类外发风险：PII 外泄（身份证/手机号/邮箱）、密钥外泄（明文 API Key/私钥/账号密码）、商业敏感（报价/合同/路线图）、内部文档（内网/员工/薪酬）、分类缺失（有敏感内容却无密级标签）、溯源缺失（有敏感内容却无溯源标记）。
- 算**外发泄露指数（0-100）**，按严重度优先级链给判定：极端 / 高 / 中 / 低。高或极端时返回码 4（已拦截，建议不要直接外发）。
- 标出每条命中的**可溯源性**：同文件带密级/水印/canary/分类标签即「可溯源」（泄露后还能追到副本与经手人），无标记即「不可溯源」（泄露后追不回来）。这是本包原创的量化点。
- 量化**安全控制价值**（避免的溯源补救与泄露处置工时），并聚合出 `guard-ledger.md` 价值账本。
- 落**实物报告**（share_report.md + 机器可读 JSON 尾块），不是日志。

不能做的（诚实边界）：
- 不实际拦发送、不修改文件，决策权在你（看清后果再决定，不硬禁止）。
- 对文件最终是否真的发出、发给谁、通过什么渠道无感知。
- 不解析二进制实为图片/加密压缩包的内容（需先看原文）。
- 不承诺 100%：变量改名、间接引用会漏；个别普通字段会被误报。规则仅作提示。
- 不评估数据真实敏感度，只量化静态可见风险。

## 怎么用

```
python scripts/guard.py scan <目录>            # 扫描并出 share_report.md，高/极端返回码 4
python scripts/guard.py scan <目录> --json     # 同上加 --json 输出结构化命中
python scripts/guard.py rules                  # 列出 12 条外发泄露护栏规则
python scripts/guard.py ledger <目录>          # 聚合该目录下所有 report 生成价值账本
python scripts/guard.py version                # 打印引擎版本
```

退出码：0 通过 / 1 参数错 / 2 IO·运行错 / 3 未知命令 / **4 已拦截（高/极端风险）**。

## 报告长什么样

扫描后生成 `share_report.md`，含四节：判定（风险等级 + 外发泄露指数 + 可溯源性 + 处置建议）、命中汇总、命中清单（含可溯源/不可溯源标注）、安全控制价值量化，末尾附机器可读 JSON。把报告贴进对话或发给相关人，即是「我已对外发内容做过审查」的实物证据。

## 与其它 guard 包的关系

- 与 guard-privacy：privacy 管「代码里的 PII 字段处理」（开发态、字段级），share 管「整个文件外发前的内容边界」（外发态、文件级）。
- 与 guard-secret：secret 管「密钥字段的存储与调用」，share 管「密钥字面随文件外发」。
- 与 guard-network：network 管「代码里的外联通道」，share 管「文件外发的边界」——通道与文件两条线。
- 与 guard-publish（规划中）：publish 管「发布前综合合规」，share 是其中「外发内容边界」这一专项。
