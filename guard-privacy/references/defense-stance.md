# 设计立场与诚实边界（guard 系列统一）

## 立场：看清后果再决定，不硬禁止

guard 系列每个包都守同一条线：**护栏的价值在让人看清风险，不在替人拦**。具体到 guard-privacy：

- PII 处理是业务必需（实名、配送、客服都要用到身份信息），全禁等于不干活。
- 硬禁止会逼人把 PII 藏进更隐蔽的字段名、或塞进加密信道后再明文打印——越禁止，越难检测，结局更坏。
- 所以本工具只做量化与提示：PII 暴露指数、可脱敏性、避免损失工时，决策权交还人。

## 诚实边界（必须写明，不承诺 100%）

1. **只静态检测，不实际拦数据。** 工具跑完，代码该落库还落库。拦不拦是你的运行时策略。
2. **对运行时真实数据流向无感知。** PII 是否真被落库/外传、是否已被脱敏——本工具不知道。
3. **启发式正则，漏报与误报并存。** 变量改名、间接引用、解密再打印都会漏；个别普通 `name`/`email` 会被误报。规则仅作提示。
4. **可脱敏性不是"已脱敏"保证。** 维度只提示"这些暴露可经治理"，是否真脱敏须结合脱敏函数与人工确认。
5. **不评估数据敏感度等级，只量化静态可见风险。**

## 退出码约定（全系列一致）

| 码 | 含义 |
|----|------|
| 0 | 通过（低危或无命中） |
| 1 | 参数错（缺目录 / 路径不存在） |
| 2 | IO·运行错（资源解析失败 / 报告写入失败） |
| 3 | 未知命令 |
| 4 | 已拦截（高/极端风险，建议不要直接上线） |

## 安全控制价值量化

把"没发生的泄露"折算成可感知数字：极端 8h / 高 4h / 中 1h / 低 0h 的脱敏治理与合规排查工时。这是把合规成本语言化，让脱敏投入有依据，而非"账本"拟人化包装。

## 与系列其他包的衔接

- 与 guard-secret：secret 管"密钥字段"（凭证），privacy 管"PII 字段"（人相关的敏感信息）——前者防凭证泄露，后者防个人信息泄露。
- 与 guard-network：network 管"代码里的外联通道"，privacy 管"外联里带的是什么（PII）"——通道与内容两条线。
- 与 guard-share（规划中）：share 管"整个文件外发前查边界"，privacy 管"代码里的 PII 字段"——文件级 vs 字段级。
