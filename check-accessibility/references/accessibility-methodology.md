# 可访问性基线护栏 方法论（check-accessibility）

本文件说明 check-accessibility 能判定什么、不能判定什么，以及各类规则背后的取舍。

## 一、能确定性判定的（本包范围）

1. img 缺 alt：<img> 无 alt 属性，屏幕阅读器无法传达图片内容，定为高级（限 html/htm/jsx/tsx/vue/svelte/md）。
2. 按钮无标签：<button> 既无文字也无 aria-label，交互目标对辅助技术不可识别，定为中级（限组件类扩展名）。
3. html 缺 lang：<html> 无 lang 属性，语言与发音无法正确选择，定为中级（限 html/htm）。
4. 无 title：HTML 文档无 <title>，标签页与书签无标识，定为低级（限 html/htm）。
5. 标题层级跳跃：标题从 h1 直接跳到 h3（跨越超过一级），大纲结构断裂，定为低级（限 md/html/htm）。
6. 已接入可访问性基线：命中 a11y/accessibility/无障碍，定为安全变体（仅鼓励信号，不计入发现项）。

## 二、不能判定、也不假装能判定的

1. 颜色对比度不足、键盘焦点陷阱、表单标签关联：本包不渲染、不跑屏幕阅读器、不做交互探测，会漏报这类需要渲染或交互才能判定的问题。那是专业 WCAG 审计的活。
2. ARIA 用法是否正确（如 aria-hidden 嵌套焦点）：本包只查「有没有标签」，不查「标签用得对不对」。
3. 动态内容的可访问性（如异步加载区域的 live region）：本包只看静态文本，不建模运行时行为。

## 三、严重度设定

- 高：img 缺 alt（A11Y-IMG-NO-ALT）。视障用户直接丢失图片信息，是最直接的无障碍硬伤。
- 中：按钮无标签、html 缺 lang。交互目标不可识别、语言无法正确选择，定为中级并建议修复。
- 低：无 title、标题层级跳跃。可读性与导航缺口，但不如前述致命。
- 安全变体：已接入可访问性基线，仅鼓励信号，不计入发现项、不影响判定。

## 四、为什么用「模式匹配」而非实时执行/渲染

实时渲染与屏幕阅读器仿真需要浏览器环境与人工，慢、难进 CI、结果不稳定。本包只用不需要渲染的确定性模式，因此可重跑、可留证据、可进 CI，专门拦住「img 缺 alt / 按钮无标签 / html 缺 lang / 无 title / 标题层级跳跃」这类一眼就能揪的无障碍硬伤。

## 五、如何扩展规则库

直接编辑 resources/rules.json，追加 {"id": "...", "layer": "...", "kind": "regex", ...} 即可，引擎在每次扫描时实时加载，无需改代码。
