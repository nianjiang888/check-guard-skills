# 防御立场与诚实声明（check-accessibility）

本文件说明 check-accessibility 在「帮你拦住可访问性基线护栏雷区」这件事上的立场与边界。它不是执行/渲染引擎，而是一道可重跑、可量化、留证据的静态防线。

1. 只做不需要渲染的确定性模式：img 缺 alt、按钮无标签、html 缺 lang、无 title、标题层级跳跃。这些恰恰是「人容易看漏、工具一眼揪出」的低垂无障碍硬伤。
2. 不做屏幕阅读器仿真与对比度计算（发现「对比度不足」「键盘焦点陷阱」），也不做 ARIA 正确性校验。那超出了静态快检的能力，强行做只会制造误报。
3. 不承诺 100% 准确：img 缺 alt 几乎零误报，但按钮/标题在特殊写法下可能误报；报告里每条都标注命中类型（如「<img> 缺少 alt 属性」），由人最终裁决。
4. 不修改文件：只产出报告与机器可读判定块，是否修复、怎么修复由使用者决定。不替你改页面，避免「自动修正」引入新问题。
5. 不拦截部署：返回退出码供 CI 消费，但是否阻断由流水线策略决定；本批规则最高严重度为「高」，未启用极端级（退出码 4 保留给未来扩展）。
6. 每条发现都带「可修正 / 不可修正」标记（无障碍硬伤一律「可修正——补 alt/标签/lang/title」），并汇总成「验证暴露指数」与「预计避免返工工时」，让可访问性风险从「感觉不够友好」变成可比较、可追踪的数字。
