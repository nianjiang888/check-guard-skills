# FAQ：guard-cost API 花费熔断

## 1. 它会替我拦下会烧钱的调用吗？

不会「替」你拦。它的「拦截」是信息层面的：扫描到高/极端成本雷区时，报告明确标「建议不要直接上线」，退出码置 4（已拦截）。但真正上不上线、加不加预算，永远是你自己。这个设计是刻意的——硬禁止会逼人绕过，那更糟。

## 2. 运行时实际发出的请求它能管到吗？

管不到。它只看被扫描的代码文本里写着的模式（while True 调 API、没预算常量、没熔断装饰器）。你运行时动态调了多少次、每次多大，它感知不到。所以它该和真实计量（账单告警、用量看板）配合，不是替代。

## 3. 为什么「缺预算」只报中危，不直接拦？

因为缺预算在很多合理场景里存在（内部脚本、一次性任务），直接拦会制造大量误报，用户学会忽略后真正的危险也被忽略。本包对「缺护栏」给中危提示鼓励补齐，对「while True 调付费 API」「密钥硬编码」这种明确灾难才给极端/高。宁可在边界上保守，也不狼来了。

## 4. cap 的花费投影准吗？

仅供参考。投影按 `cost-models.json` 里的公开参考单价（标注为 USD 参考价）乘以你给的次数和 token 数。真实花费受缓存、批处理折扣、套餐赠送、厂商调价影响，永远以服务商账单为准。cap 的价值是「上线前先有个数量级概念」，不是精确报价。

## 5. 判定为什么按「优先级链」而不是平均？

因为成本风险由最坏那一项决定。一个功能同时有「缺预算（中）」和「while True 调 API（极端）」，平均只会稀释危险。规则是：命中任意极端即为极端，否则看最高一级。

## 6. 价值账本的「避免 8 小时」是精确测算吗？

不是精确值，是可感知的折算。无护栏付费调用的代价在「账单日才显现」——对账、定位超支点、止损、安抚业务方，综合下来极端约 8 小时、高约 4 小时、中约 1 小时。目的是让成本防护的价值可见，不是做工时审计。

## 7. 误报了怎么办？比如我的 for 循环其实有上限。

复合规则只在「文件确实含付费 API 调用」且「缺失对应护栏」时才提示，正常带预算/熔断的代码大多不会被标高危。若仍误报，可调整 `resources/rules.json` 的 `allowlist.paths` 跳过敏感目录，或在源码全局 `ALLOW_KEYWORDS` 增删白名单词。注意：白名单在引擎常量里，改 JSON 的 patterns 不生效。

## 8. 它能当团队的成本评审工具吗？

可以当一个轻量环节。把含大模型调用的 PR 跑一遍 `scan`，产出的 `cost_report.md` 是可存档证据；多次报告用 `ledger` 聚合成价值账本，便于复盘「这个月拦下了多少成本先兆」。但它不替代预算系统、不替代限流中间件、不替代账单告警。

## 9. 和系列其他 guard 包什么关系？

平行独立。guard-secret 守凭据、guard-prompt 守提示注入、guard-delete 守破坏性操作、guard-cost 守花费——各自一个专业安全域，互不依赖、可单独使用。统一约定是退出码第 4 态=已拦截、纯标准库零依赖、留可审计产物。
