# check-links 的防御立场（诚实边界）

check-links 的定位是「死链 / 坏引用护栏」，不是「链接监控器」，也不是「发布门禁」。它的立场和 guard / check 系列一致：**看清后果再决定，不替你做决定**。

## 我们做什么

- 在文档/代码/配置上线前，用静态规则把常见的、低垂的、高代价的死链与坏引用扫出来。
- 把每一个问题量化：严重度、可修正性、验证暴露指数、预计避免返工工时。
- 产出可复核的报告文件和机器可读的判定块，作为发布前的「证据」。

## 我们不做什么

- **不修改你的文件**。发现即报告，改不改、怎么改由你决定。
- **不拦截部署**。退出码 4（极端）只是「建议阻断」，是否真阻断由你的 CI 策略决定。
- **不实际发起网络请求**。我们不做实时探活，只做静态可解析性判定，因此不受网络/墙影响、可重跑。
- **不感知运行时**。我们看不到链接点开之后到底对不对，只基于文件可见内容判定。
- **不承诺 100% 准确**。误报会杀死一个检查工具，所以白名单与文件存在性判定是第一优先级。

## 为什么不做「硬禁止」

如果一个检查工具动不动就「禁止提交」「强制阻断」，用户会绕过它（改名、加例外、关掉检查）。check-links 选择「把死区划出来 + 把代价算清楚」，让工程师自己判断——这比强制更可持续，也更诚实。

## 价值量化是估算

「预计避免返工工时」是基于严重度的经验折算（极端 8 小时 / 高 4 / 中 1 / 低 0），不是精确会计。它的作用是让「死链雷区」变成可感知的数字，而不是消失在「应该没问题吧」的侥幸里。真实代价以你的故障记录为准。
