# guard-prompt · 提示注入检测

## 一、干什么

guard-prompt 是 AI 处理**不可信内容之前**的一道静态安检。它做三件事：

1. **三维检测**：指令劫持信号（精度）→ 结构/分隔符注入（抓隐蔽机制）→ 意图目标（抓目的），覆盖直接注入与间接注入。
2. **判定 + 出报告**：给出低 / 中 / 高 / 极端四级风险判定，生成可存档的 `injection_report.md`，标注注入类型（直接/间接）、意图目标（数据外传/越权等）、命中位置。
3. **折算价值**：把"拦下的注入攻击"折算成可感知数字，累积成安全控制价值账本。

定位上，它是 Agent 读取网页、文档、邮件、检索结果、工具返回**之前的守门员**——不是运行时拦截器，而是内容进执行前的静态体检。

## 二、主动触发

当 Agent 准备读取外部网页、把检索文档喂给模型、处理用户发来的长文本、或把内容写入记忆/知识库之前，主动建议先跑一轮 guard-prompt 扫描；当用户提到"这段有没有藏着指令 / 网页会不会有注入 / 检索结果有没有投毒 / 有人套我系统提示词"时，直接调用本技能做扫描，而不是凭肉眼翻内容。

## 三、理论地图

- **OWASP LLM01:2025 与直接/间接分类**（references/owasp-llm01.md）：提示注入为什么是榜首高危、两种基本形态、以及 Transformer 一视同仁的架构级根因。
- **防御层级与诚实边界**（references/injection-defense.md）：文本层/模型层/执行层三层防御，本工具落在执行层前置；以及"拦不住什么"的诚实声明。
- **间接注入深潜**（references/indirect-injection.md）：RAG 投毒、多模态注入、上下文污染——为什么"结构注入"和"意图目标"必须作为独立维度。

## 四、快速上手

```bash
# 扫描目录，生成 injection_report.md（高/极端会退出码 4 拦截）
python guard.py scan <目录>

# 查看三维检测规则库
python guard.py rules

# 聚合多份扫描报告，生成安全控制价值账本
python guard.py ledger <目录>
```

## 五、子命令速查

| 子命令 | 作用 | 退出码要点 |
|---|---|---|
| `scan <目录>` | 三维扫描 + 出报告 | 高/极端 → 4（已拦截） |
| `rules` | 打印三维检测规则库 | 0 |
| `ledger <目录>` | 聚合报告生成价值账本 | 0 |
| `version` | 打印引擎版本 | 0 |

参数错 → 1，IO/运行错 → 2，未知子命令 → 3，已拦截 → 4。

## 六、边界声明

- **能做的**：静态提示注入检测、输出可存档报告、标注注入类型与意图目标、折算拦截价值。
- **不能做的**：运行时实时拦截（不挂在推理链路里）、多模态内容分析（不读图片/音频里的视觉指令）、保证 100% 拦住所有注入（架构级缺陷，无单点银弹，本工具目标精度 90–95%）。
- **隐私**：扫描全程在本地进行，不向外发送被扫目录的任何内容。
