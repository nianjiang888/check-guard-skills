# guard-prompt 常见问题（按你会怎么问组织）

## 用户发来的话里写了"忽略上面指令"，这算注入吗？
算，而且是最典型的**直接注入**。本工具的 hijack 维度会命中「忽略/无视 + 上面/之前 + 指令/提示」这类组合，判定为极端并拦截（退出码 4）。但注意：判定是"机器替你看见风险"，不是替你拍板——你仍要决定这段内容要不要喂给模型。

## 它说"高"，我就绝对不能用这段内容吗？
"高"的语义是"拦下，需人工确认后再决定"。意思是检测到了高确信度的注入信号（比如伪造 `<system>` 标签、HTML 注释藏指令、或明确的数据外传意图）。你要看清具体是哪条、来自哪个文件、是不是真被污染，再决定隔离还是放行。

## 直接注入和间接注入有什么区别？
直接注入是攻击者把恶意指令**直接写进对话**（"忽略上面指令"）；间接注入是恶意指令**藏在模型会读取的外部内容里**（网页、检索文档、邮件、图片描述）。间接注入更危险——攻击者根本不碰你的对话，只污染你的数据。本工具两者都查，并在报告里标出注入类型。

## 为什么"假设你是我的英语老师"这种话只报"中"不拦截？
角色覆盖（"你现在是/假设你是"）属于软性指令劫持，在合法角色扮演里也常见，单独出现误报成本高。所以本工具把它定为"中"（提示留意、不阻断）。真正会拦截的是带明确覆盖系统设定（"重置你的系统提示"）或越狱口令（"developer mode/DAN"）的硬信号。

## 合法内容里出现"发送邮件给客户"会被误报吗？
不会。数据外传意图（INTENT-EXFIL）的判定要求"发送到/外传/泄露/上传到 + 外部/我/邮箱/服务器/http"这样的外发目的地。普通"写邮件给客户"不含外发目的地，不会命中。误报控制是本工具的设计重点——告警疲劳会杀死安全产品。

## 它能不能 100% 拦住注入？
不能，也不该这么宣传。提示注入是 Transformer 架构级缺陷（模型无法区分指令与数据），学界共识无单点银弹。本工具三维检测（指令劫持 + 结构注入 + 意图目标）目标精度 90–95%，且诚实声明拦不住多模态注入（图片藏指令）、语义级软注入、高级指令-数据混淆。

## 和 guard-secret 有什么区别？
guard-secret 管"代码里的密钥字段"（凭据泄露），guard-prompt 管"内容里的隐形指令"（提示注入）。一个查密钥、一个查指令，对象完全不同，可同时用在"提交前体检"这一步。

## 扫描规则我能改吗？
能。`resources/rules.json` 是规则库，新增/调整正则规则或严重度改这个文件即可，不用动引擎代码。每条规则含 id / layer / name / category / severity / intent / pattern。
