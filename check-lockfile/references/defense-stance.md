# 防御立场与诚实声明（check-lockfile）

本文件说明 check-lockfile 在「帮你拦住依赖锁定完整性护栏雷区」这件事上的立场与边界。它不是执行/渲染引擎，而是一道可重跑、可量化、留证据的静态防线。

1. 只做不需要语义理解的确定性模式：浮动版本、缺完整性哈希、明文 http 源、未解析标记。这些恰恰是「人容易看漏、工具一眼揪出」的低垂锁定缺口。
2. 不做实时依赖解析与漏洞情报比对（发现「版本有已知漏洞」「传递依赖冲突」），也不做供应链溯源。那超出了静态快检的能力，强行做只会制造误报。
3. 不承诺 100% 准确：明文源/浮动版本几乎零误报，但缺哈希在某些本地路径依赖格式下可能误报；报告里每条都标注命中类型（如「锁文件从明文 http 源拉取依赖」），由人最终裁决。
4. 不修改文件：只产出报告与机器可读判定块，是否修复、怎么修复由使用者决定。不替你改锁文件，避免「自动修正」引入新问题。
5. 不拦截部署：返回退出码供 CI 消费，但是否阻断由流水线策略决定；本批规则最高严重度为「高」，未启用极端级（退出码 4 保留给未来扩展）。
6. 每条发现都带「可修正 / 不可修正」标记（锁定类缺陷一律「可修正——补全精确版本/哈希/改 https 源」），并汇总成「验证暴露指数」与「预计避免返工工时」，让依赖风险从「感觉不踏实」变成可比较、可追踪的数字。
