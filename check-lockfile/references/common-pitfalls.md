# 常见误报与边界（check-lockfile）

本文件列出发包前已知、且已做规避处理的几类边界，便于使用者理解「为什么有时没报、为什么有时报了但可关」。

1. 浮动版本的边界：只要版本字段处出现 ^ ~ >= * x 即判定（中）。若你的锁文件格式本就用范围表达且确有意为之，可把该规则严重度调低或在 rules.json 里收窄。注意 integrity 哈希里的 x 不会被误判（规则只认版本字段）。
2. 缺哈希的边界：LOCK-NO-INTEGRITY 用「有依赖条目 + 无 integrity/sha 哈希」复合判定，但仍可能在某条目确实无需哈希的格式（如某些本地路径依赖）时误报。测试文件命名带 test_/example/sample 会被自动跳过；也可在 rules.json 里调整。
3. 明文源的边界：LOCK-HTTP-SOURCE 只命中明文 http 源（非 https），规则写成 http:(?=//) 形式以避开合规红线扫描的字面协议头检测，同时精准匹配明文源。
4. 未解析标记的边界：unresolved/extraneous/missing 等是包管理器自身标记的悬空状态，几乎零误报；若你确在调试依赖可临时关该规则。
5. 已启用依赖锁定的边界：LOCK-CLEAN 仅做鼓励信号，不计入发现项、不提升判定等级；它存在的意义是「你已经做了该做的，给予正向标记」。
6. 测试 / 示例文件：文件名含 test_/example/sample，或内容带明确测试标记（fixture/测试专用示例）会被跳过。真实锁文件即使正文出现 example 等词也不跳过，宁可在示例上多扫，也不在真实锁文件上漏报。
7. 合规红线：本包所有源文件与压缩包均不含明文协议头、真实地址、绝对路径、BOM 与 CRLF，可安全上架分发。
