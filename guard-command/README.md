# guard-command 使用说明

> 系列：guard-*（12 条独立专业安全域）｜ 成员 #7：高危命令 / 危险参数拦截
> 引擎版本：2.0.0 ｜ 零依赖（Python 标准库），装了即跑

## 一、它解决什么问题

高危命令一旦真跑，代价在「回车」那一刻就定了。guard-command 在脚本上线前静态扫一遍危险命令与危险参数，把风险算清楚。

## 二、子命令

| 子命令 | 作用 | 退出码 |
|--------|------|--------|
| `scan <目录>` | 扫描目录，出 `command_report.md`（判定/暴露指数/命中清单/价值量化） | 0 通过 / 4 已拦截 / 1 参数错 / 2 IO 错 |
| `rules` | 列出 12 条高危命令规则库 | 0 |
| `ledger <目录>` | 聚合目录下所有 `command_report.md`，生成 `guard-ledger.md` 价值账本 | 0 / 1 无报告 |
| `version` | 打印引擎版本 | 0 |

| 退出码 | 含义 |
|--------|------|
| 0 | 通过（低危/干净） |
| 1 | 参数错（缺路径/路径不存在） |
| 2 | IO·运行错（资源解析失败/报告写入失败） |
| 3 | 未知命令 |
| 4 | 已拦截（高/极端风险，建议不要直接上线） |

## 三、六层检测（12 规则）

| 层 | 规则 | 严重度 | 一句话 |
|----|------|--------|--------|
| 文件系统破坏 | CMD-RM-RF | 极端 | 递归强制删除 rm -rf /，整树删除不可恢复 |
| 磁盘/设备 | CMD-DD-DISK | 极端 | dd 直写块设备，整盘覆盖 |
| 磁盘/设备 | CMD-MKFS | 极端 | 格式化/分区，原数据报废 |
| 磁盘/设备 | CMD-DEV-REDIRECT | 极端 | 输出重定向到 /dev/*，等同覆写磁盘 |
| 进程自杀 | CMD-FORKBOMB | 极端 | fork bomb，拖垮整机 |
| 权限/提权 | CMD-CHMOD-777 | 高 | 全员可写，任意篡改 |
| 权限/提权 | CMD-CHMOD-000 | 高 | 自我锁死，运维事故 |
| 权限/提权 | CMD-SUDO-SU | 高 | 常驻 root，违反最小权限 |
| 网络执行 | CMD-PIPE-SH | 高 | 网络下载直输 shell，任意执行 |
| 版本控制 | CMD-VCS-FORCE | 高 | git --force/reset --hard/clean，历史丢失 |
| 版本控制 | CMD-NO-VERIFY | 中 | 跳过提交钩子，质量门形同虚设 |
| 安全变体 | CMD-SAFE-DRYRUN | 低 | --dry-run / rm -n（鼓励，不当命中） |

## 四、原创量化点

- **命令危险暴露指数（0-100）**：严重度权重累加（极端 100 / 高 40 / 中 12 / 低 3），封顶 100。
- **判定优先级链**：极端 > 高 > 中 > 低，按最坏一项定级，不被平均稀释。
- **安全控制价值量化**：把「没发生的误操作」折算成可感知工时（极端 8h / 高 4h / 中 1h / 低 0h）。
- **可回滚性维度**：每条命中标「可回滚/不可回滚」。

## 五、典型用法

```bash
# 扫一个部署脚本目录，看有没有危险命令
python scripts/guard.py scan ./deploy

# 聚成团队账本
python scripts/guard.py ledger ./scan_outputs
```

## 六、诚实边界

不实际拦截命令；不感知运行时真实执行情况；不承诺 100% 拦住；危险后果取决于命令是否真被执行，本工具只量化静态可见风险。误报会杀死产品，故危险命令本体做了边界收敛（rm -rf 而非任意 rm、777 而非 755）。

## 七、文件导航

- `scripts/guard.py` 主引擎
- `resources/rules.json` `command-models.json` `command-domains.json` 规则与模型
- `references/` 最小权限 / 能力安全·爆炸半径 / 防御立场
- `examples/` 极端 / 高 / 中 / 干净 四份样例报告
