# 香农熵与密钥检测

> guard-secret 第二层检测（召回层）的理论根基。本篇把"为什么算熵能找密钥"讲清楚——从 1948 年的信息论源头，到今天的密钥扫描实践。

## 一、信息熵的定义

1948 年，克劳德·香农（Claude Shannon）在《通信的数学理论》中给出信息熵：

> H = −Σ p(x)·log₂ p(x)

其中 x 是信源可能出现的符号，p(x) 是它出现的概率。熵度量的是一个序列的"不可预测程度"——或者说"看起来有多随机"。

直觉上很容易理解：一段全是 `aaaaaaa` 的文本，每个字符都可预测，熵接近 0；一段真正随机生成的密钥，每个字符都等可能，熵接近该字符集的理论上限。

## 二、为什么熵能区分"密钥"和"普通文本"

人类写的代码和文档，字符分布极不均匀：空格、字母 e、常见单词反复出现，熵很低。而密码学意义上的密钥、令牌、随机串，是刻意从大字符空间均匀抽取的，熵很高。

这正是密钥检测的核心洞察：**高熵 = 高随机 = 大概率是机器生成的秘密，而非人写的内容**。

不同字符集的熵上限不同：

- **十六进制串**（0-9a-f，16 个符号）：上限 log₂(16) = **4.0 bits/字符**。
- **Base64 串**（A-Za-z0-9+/=，约 64 个符号）：上限约 **6.0 bits/字符**。
- **通用可打印字符**（更多符号）：上限约 **6.5 bits/字符**。

一个真正随机的 hex 串，其熵会非常接近 4.0；而一段人写、重复、有结构的 hex（比如 `1234567890abcdef` 反复）熵会明显低于 4.0。所以阈值设在"接近上限"的位置——只有接近随机分布的串才被标记。这正是 guard-secret 的 `hex>4.0 / base64>4.5 / 通用>4.5` 三个阈值的来历。

## 三、一个具体例子

假设扫描到一个 40 字符的串：

- `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`：每个字符都是 a，熵 = 0。明显不是密钥，放过。
- `0123456789abcdef0123456789abcdef01234567`：规律递增，熵远低于 4.0。放过。
- `9f3Kp2Qx7mBv1Rte8Wn4Yc6Hd0Ls5Aj3Fg9Zq2Kp7X`：肉眼难辨规律，实测熵接近 4.0+。标记，进入上下文层判定。

熵层不关心"这是什么密钥"，只关心"它够不够随机"。这恰好补上了正则层的盲区——正则只认得已知的格式（AWS、JWT…），而熵层能抓住**任何格式的高随机串**，包括团队自造的内部 token。

## 四、熵层的失败模式（必须诚实说明）

熵不是银弹，它有两个公认的失败模式，这也是为什么 guard-secret 一定配三层而不是单用熵：

1. **被 base64 测试数据淹没**。很多正常的测试 fixture、编码后的样本数据，本身就是高熵的。如果只靠熵，会告警疲劳。解决：第三层上下文白名单——串周围若是 `example`/`test`/`dummy`/`placeholder`，直接放过。
2. **漏掉低熵密钥**。少数系统用词典词做"密钥"（弱密钥），熵不高，熵层抓不到。解决：第一层正则专门匹配弱密码赋值 `password = "123456"` 这类，与熵层互补。

所以单用熵不行，单用正则也不行。两者相加，再叠上下文降误报，才接近生产可用的 90–95% 精度。这背后就是安全工程里反复强调的"纵深防御"思想。
