# FAQ：场景 → 怎么用

## 一、按使用场景查

| 场景 | 该怎么做 | 说人话 |
|---|---|---|
| 标书刚写完，想整体过一遍 | `scan 标书目录/` | 全部 31 条规则都跑，出完整报告 |
| 只想快速看看有没有致命伤 | 跑完看报告最上面几行 | 判定是"极端"或"高"的，先处理那几条 |
| 临交标了，只剩半小时 | `scan` 后只看"高"和"极端"两档 | 低危的页码、字数问题来不及就别管了 |
| 标书是 Word/PDF | 先转成 .txt 或 .md 再跑 | 本包读纯文本，扫描件要先 OCR |
| 想在提交流程里自动卡一道 | `scan` 后判断退出码 | 非 0 就拦下来，4 是必废标项 |
| 想接入自己的脚本/平台 | 用 `ledger` 命令 | 输出 JSON，字段见下 |

## 二、按看到的结果查

| 报告里看到 | 什么意思 | 怎么办 |
|---|---|---|
| 判定"极端"，退出码 4 | 命中必废标项（如报价超限） | 必须改，改完重跑 |
| 判定"高" | 有资格性或形式性硬伤 | 逐条补材料，注意截止时间 |
| 判定"中" | 有一致性或响应性问题 | 人工核对，多数能改 |
| 判定"低" | 观感与低级错误 | 有余力就改 |
| 判定"通过" | 31 条规则都没命中 | 不代表一定中标，只代表这 31 个坑没踩 |
| 预计避免损失 ¥1450000 | 严重度换算的量级提示 | 不是精算，用来判断值不值得改 |

## 三、按疑问查

| 疑问 | 回答 |
|---|---|
| 为什么干净标书也可能有提示？ | `date`/`amount` 规则在日期≥3处、金额≥4处时会提示"需人工核对"，这是善意提醒不是判定缺陷。若确认无误可忽略 |
| 报了"缺资质证书"但我明明附了 | 检查用词，本包认"资质证书""资质等级"两种叫法，其他叫法可能漏检。也确认是不是放在扫描件里没进文本 |
| 工期倒挂会不会误报？ | 不会。这条规则会真解析开工/竣工日期再比大小，只有确实倒挂才报 |
| 报价超限是怎么判出来的？ | 依赖标书里出现"超出/高于/高出/超过……限价"这类表述。若你只写了金额没写限价关系，本包判不出来，需自己核 |
| 能不能改规则？ | 能。规则全在 `resources/rules.json`，改 JSON 不用动代码。改完跑 `scripts/smoke_test.py` 确认没跑坏 |
| 为什么样例文件叫 tender-demo 而不是 sample-？ | 引擎白名单会跳过 sample/test/example 开头的文件，样例标书若叫 sample-* 会被直接跳过，一份都扫不出来 |
| 免费版和付费版差什么？ | 免费版跑 10 条基础规则（资质、签章、工期），付费版跑全量 31 条并附逐条修改建议 |

## 四、退出码速查

| 码 | 含义 |
|---|---|
| 0 | 干净，无命中 |
| 1 | 有命中，未到极端 |
| 2 | 输入/输出错误（路径不存在、规则文件读不了） |
| 3 | 命令写错 |
| 4 | 命中极端项（必废标） |
